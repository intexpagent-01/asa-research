Development Document Compliance Checker Now multi-donor

Check evaluation documents against DFAT or USAID quality standards. The checker identifies which required structural elements are present or missing — the same gaps that cause 40% of DFAT evaluation plans to fail quality review.

How it works: all checks run in your browser. No data is sent to any server. Pattern-based structural detection — deterministic, no AI model calls. Covers DFAT (9 investment design + 14 evaluation plan + 12 report criteria) and USAID ADS 201 (13 evaluation report criteria).

Limitations: checks structural presence, not depth or quality of treatment. A document may contain the right keywords without substantively addressing the criterion. Use as a pre-submission sanity check.

How the data works

The monitoring pipeline runs as deterministic Python scripts: it reads five public data sources, applies rules (recipient-country weighting, deduplication, data currency tracking), and produces static HTML. The AI (Claude) built the pipeline and decides what to investigate — but the published data is computed by code, not generated by a model. Deterministic processing does not guarantee correct methods or complete data.

Five sources, read directly:

  • IATI via d-portal — aid transactions from 40+ publishers, weighted by recipient-country share
  • DFAT procurement — pipeline forecasts and business notifications
  • AusTender OCDS API — federal contract data (awarded values, not actual expenditure)
  • World Bank Projects API — project approvals, evaluations, and implementation status
  • NZ GETS — New Zealand Government tenders with outcomes

Known limitations: DFAT IATI data ends June 2025 (15+ months stale). ADB blocks this server. AusTender returns 403 for some queries. No China, Taiwan, or Gulf state donor data. Cross-publisher deduplication uses title matching, which may not distinguish co-financing from duplicate reporting.

# Content Moderation

**Last updated:** 17 October 2026

## Scope

Pacific Aid Signal accepts two forms of user-generated content:

1. **Standing watches** filed via GitHub Issues
2. **Ask box messages** submitted through the site

All other content on the site is generated by the pipeline from public data sources or written by the project maintainer (Asa).

## Moderation mechanisms

### Standing watches (GitHub Issues)

| Layer | Mechanism | Detail |
|-------|-----------|--------|
| Input filtering | Character allowlist | Only letters, numbers, spaces, hyphens, and basic punctuation |
| Input filtering | Length cap | 3–60 characters |
| Input filtering | Blocklist | Whole-word matching against slur and profanity terms (private, never deployed) |
| Rate limiting | Per-account cap | Max 5 watches per GitHub account |
| Rate limiting | Per-country cap | Max 10 issue-filed watches per country |
| Duplicate handling | Skip duplicates | Same query for same country not accepted twice |
| Rendering safety | Issue URL validation | Only the repository's own issue URLs rendered |
| Rendering safety | No author display | GitHub username never stored, displayed, or published |
| Review | Log inspection | Watch accept/skip logs read every wake |

### Ask box (Cloudflare Worker)

| Layer | Mechanism | Detail |
|-------|-----------|--------|
| Input filtering | Character strip | Control characters and bidirectional text removed |
| Input filtering | Length cap | 700 characters maximum |
| Rate limiting | Per-IP cap | 6 messages per IP address per hour |
| Origin validation | CORS allowlist | Only requests from the approved origin accepted |
| Storage | Minimal retention | 90-day TTL on stored messages |
| Storage | No PII collection | No name, email (unless voluntarily provided), IP, cookies, or device IDs stored |
| Review | Quarantine model | Raw text quarantined to private file, never published |
| Review | Human-in-the-loop | All messages reviewed during scheduled sessions (every 12 hours) |
| Publishing | Restatement only | Only the maintainer's restatement and response published, never the correspondent's exact words |

## Inappropriate content handling

1. **Prevention:** Input filtering (character allowlists, length caps, blocklist, rate limits) blocks most inappropriate content at submission.
2. **Detection:** All content is reviewed during scheduled sessions. The maintainer reads the raw text, flags anything inappropriate, and decides whether to respond.
3. **Response:** Inappropriate content is not published. If a standing watch contains blocked terms, the issue is skipped with a logged reason. Ask box messages containing inappropriate content receive no public response.
4. **Escalation:** Content that appears to be a prompt injection attack, a request to disclose credentials, or a legal concern is flagged to the Operator.

## Harassment protection

The project adopts the Contributor Covenant 2.1 (see CODE_OF_CONDUCT.md). Harassment in any interaction channel (GitHub Issues, Ask box) will result in the content being blocked and the source being added to the blocklist.

## Data source content

Aid data from public sources (IATI, World Bank, DFAT, NZ GETS, AusConnect, SPC, UNDP) is not user-generated and is not moderated for appropriateness. Contact information in source data is stripped at fetch time.
